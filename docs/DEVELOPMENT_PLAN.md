# 用户模拟项目：一步一步的开发与验收

日期：2026-10-14。每步先完成实现与独立验收，再讲下一步；标为计划的模块不是已经存在的功能。

## 双项目边界

A 生成个性化评分/评论，B 评测与诊断。原 AgentSociety 课程代码和实验保留；不复制成第二个生成 Agent。所有项目、数据、依赖、输出位于 E 盘；数据和原报告不迁移、不覆盖。

状态基线：P0/P1 有独立离线验收记录，P3 合成 Demo 有浏览器验收；双仓契约正在开发。旧 P2 没有完整交付，不从此前的“已派发”推定完成。

## 步骤 1：安全接入与结果契约（当前）

- 目标：同一 Amazon 乐器任务进入 A，预测导出后被独立 B 读取。
- 概念：共享数据不等于共享目标标签；版本化结果契约只传预测和诊断。
- 要实现：A 独立 dry-run/合成/获准 prepared 本地 fake 导出入口；B 独立严格结果验证入口；契约来源/版本说明。
- 验收：来源和任务指纹一致；未知字段、超限、重复任务、错误四态非零拒绝；没有 GT/prompt/key；B 不依赖 A 应用安装。
- 提示：先让两个合成任务通过，再读取原已核验 prepared 的有限前缀。生成来源为 fake，不能算真实成绩。
- 参考：现有 P0 七项 gate、P1 四态与预算是必须保留的实现基础；新契约代码待独立 review 后才列作完成。

## 步骤 2：统一评分和可靠性报告（待做）

- 目标：把“看起来好”转成有分母、可手算的指标。
- 概念：评分误差、系统覆盖和运行可靠性是不同终点。
- 要实现：纯评分函数、逐任务对齐与诊断聚合、对应共同 cohort 的基线比较；显式区分 success-only 与 fallback。
- 验收：RMSE/MAE/±1/bias 手算一致；删掉一个输出不能悄悄提高覆盖；传输失败不成为普通三星预测；实际修复和任务/累计计数准确。
- 提示：先用 `[5,3]` 对 `[4,1]` 的合成例子测公式，再测失败/冷启动；不要连接 API 来验证数学。
- 参考：`rating_baselines.py`、`comprehensive_evaluation.py` 已有部分 helper，真实 Simulator 对齐门槛仍需核验。

## 步骤 3：评论诊断与幻觉记录（待做）

- 目标：分别发现风格偏差、照抄、无依据主张，而不是都归为“幻觉”。
- 概念：合法证据 ID 不代表句子被证据支持；用户星级也不是产品事实标准答案。
- 要实现：长度/重合指标、主张—证据关联与 unknown/unsupported 分类、受限条件修复，最后设计人工评审。
- 验收：植入无依据时长/价格/购买经历能被标记待核查；引用串台硬拒；不能证实时不编造事实判定；失败不写 Memory。
- 提示：先对三句手写合成文本做分类，别先做昂贵 LLM judge。
- 参考：实际渲染 registry 和字符 8-gram helper 已有；语义支持检查与完整人评未完成。

## 步骤 4：Memory 配对消融（待真实实测）

- 目标：验证是否真的被模型读取，以及读取后是否有充分效果证据。
- 概念：候选、选择、prompt 纳入与改善是四件不同的事。
- 要实现：相同任务/顺序/seed/model/render/budget 的有无 Memory 比较，整用户配对 bootstrap、暴露用户覆盖与样本不足状态。
- 验收：两条件源和任务一致；同日/未来/跨用户不能召回；零暴露不归因；不足两个 cluster 不造区间；报告全任务覆盖。
- 提示：先证明合成用户第二天读到第一天、同日不读，再批准真实模型实验。
- 参考：现有 reliable store 与四模式合同可复用；No_Memory 仍有真实历史与参考，不是无上下文。

## 步骤 5：真实行为记忆持久化（可选、待做）

- 目标：允许重启后读取获准真实事件，但不污染评测或把模型输出当反馈。
- 概念：ObservedEvent、DerivedPreference、GeneratedMemory 三类来源分离。
- 要实现：本地 SQLite、幂等写入、截至时间查询、来源重算、删除/保留策略。
- 验收：重启恢复、重复不增、删除不残留，用户/dataset/run/config/时间门槛保留；目标标签和失败生成不能变成真实行为。
- 提示：先三条合成事件完成重启与隔离测试，不先加向量库或新 Agent。
- 参考：当前 store 是进程内实现，不是数据库；详见[能力与记忆指南](AGENT_CAPABILITIES.md)。

## 步骤 6：独立演示与获批实测（待确认）

A Demo 展示安全历史→个性化模拟及错误状态；B Demo 展示确认评测配置→工具结果→受证据约束解释→确认导出。现有 P3 生成演示不替代 B 诊断演示。

真实模型实验前说明模型、数据是否外发、任务数、上下文大小、价格来源与 attempt 上限。两条件×400 任务，最多每任务 draft+repair 两次，**最坏 1,600 次请求**；不是本轮已批准预算，也不是实际收费次数。先做小规模获批 pilot 再扩大。

人工评审拟 20 配对任务/40 文本/两名真人，协议见能力指南；未确认前不组织、不付费、不编造评分。

## 每阶段通过后可讲的短文案

- 接入获准历史数据并隔离目标标签，建立生成端与独立评测端的版本化结果契约。
- 构建评分、评论代理和运行可靠性多终点评测，显式报告覆盖与失败。
- 增加实际渲染证据检查和无依据主张诊断，以有限修复及成功写入控制污染。
- 实现用户级 Memory 配对分析，区分真实暴露和效果证据，不预设收益。
- 如持久化阶段确实通过：实现来源分离、时间安全、可删除的本地行为记忆。

不写“Memory 提升”“消除幻觉”“生产级安全”或未发生的人评/真实模型成绩。旧课程汇总只保留历史身份。
