# 用户模拟 Agent：能力、评测、幻觉与记忆

日期：2026-10-14。以下区分代码能力、离线验证和未来方案；不记录真实评论、prompt 或逐任务实验产物。

## 1. 当前水平如何判断

这是一份本项目的工程成熟度划分，不是行业认证或模型性能排名。

| 级别 | 标准 | 当前状态 |
| --- | --- | --- |
| 0：提示词示例 | 单次生成评分/评论 | 已超过 |
| 1：可测试工作流 | 画像、参考筛选、结构化结果、条件修复 | 已实现；课程接口保留 |
| 2：受控离线原型 | 时间/目标隔离、证据、四态、预算、Memory 闸门、可演示 | P0/P1/P3 有离线独立验收记录 |
| 3：真实效果验证 | 新版固定任务评测、基线比较、人评、充分 Memory 暴露 | 尚未达到：真实新版结果、人评和收益证据缺失 |
| 4：持续运行服务 | 持久行为记忆、删除/隐私、稳定线上监控与框架契约 | 尚未达到，不宣称生产级 |

结论：**当前是有可靠性工程的用户模拟原型，不是已证明高质量个性化的上线系统。**没有真实生成结果和独立评审，就不能给“模拟能力强”打分。

历史 300 任务归档、2026 年 400 任务观测、现在的 Amazon 统计基线、合成 fake 验证是四种不同证据，不能合并成新版成绩。

## 2. 先冻结评测，再调整模型

1. 固定数据版本、任务身份、时间协议、模型配置、seed、预算和串行顺序。
2. 开发/验证阶段决定规则；测试标签不用于选 prompt、阈值、校准参数或任务。
3. 同任务运行有/无生成 Memory；安全真实历史和商品参考相同。
4. 先完成预测，再由评分器使用隔离目标标签；provider 为匹配/排除解析标签不等于标签参与预测。
5. 对齐任务、来源指纹与状态后才计算指标；缺失、不合法和不匹配不能静默丢弃。

## 3. 怎么衡量评分与评论

设误差 `e = predicted - actual`。评分器拟统一输出：

```text
RMSE = sqrt(mean(e²))
MAE = mean(abs(e))
±1 星准确率 = mean(abs(e) <= 1)
平均有符号偏差 = mean(e)
```

手算练习（合成，不是模型成绩）：预测 `[5,3]`，实际 `[4,1]`，误差 `[1,2]`；MAE=1.5、RMSE≈1.5811、±1 准确率=0.5、偏差=+1.5。

- baseline 固定为 global、收缩 user、收缩 item、固定 combined；不在测试集选参数。
- 分开统计：模型 success-only、含统计回退的系统预测、全请求四态覆盖。
- 两方案差异在共同有效的对应测试任务上计算，报告共同/排除任务数及用户 cluster；同时展示全请求覆盖率。
- 保留冷启动任务。不允许“失败越多，留下的样本越容易”却宣称整体改善。

评论代理指标的拟定口径：

- 长度采用 Unicode 字符数 `len(text.strip())`，明确不是 token 数；记录与安全用户历史均长的有符号/绝对差。无历史时为 NA，不默认 0。
- 相对长度差可用 `abs(generated_length - historical_mean) / max(historical_mean, 1)`；与绝对差同时报告。
- 现有 `reference_overlap_ratio` 先转小写/归一空白，统计生成文本的字符 8-gram 有多少出现在参考集合。短于 8 字时函数返回 0，但报告需注明信息不足。
- 当前重合告警阈值 0.5 是启发式，不是抄袭或真实性裁定。新报告须明确比较全文参考还是实际渲染片段，不能混用分母。
- 长度接近、低重合均不等于风格匹配或事实正确；另需真实人工评价。

## 4. 怎么衡量可靠性和 Memory

| 指标 | 分母/定义 |
| --- | --- |
| 首次格式通过率 | 首次草稿通过严格格式校验数 / 收到可检验草稿数；传输失败另列 |
| 首次完整通过率 | 首次格式、引用、质量闸门全部通过数 / 全请求任务数 |
| 修复 | 请求数、实际发送数、修复后成功数分别统计；成功率用实际发送数作分母 |
| 最终四态 | success/degraded/refused/failed 各自任务数 / 全请求任务数 |
| 调用与耗时 | draft/repair 实际 attempt、失败 attempt、工具读取、本任务/累计耗时；fake 墙时不称真实模型延迟 |
| Memory 暴露 | 候选→时间合格→选择→实际入 prompt→写入；分别记录任务及匿名用户覆盖 |
| Memory 比较 | 相同任务清单/顺序/配置；整用户配对 bootstrap，同次抽样共享且允许重复用户被抽中 |

没有任何实际 prompt 记忆暴露，不能归因收益；只有很少暴露也不能靠总体差值证明效果。空样本或少于两个用户 cluster 不生成可信区间。拟预声明最小有效样本/暴露标准，不在看到改善后临时修改。

首次“格式通过”与“完整质量通过”不同。现有 P1 诊断有原始原因与修复计数，但统一实测聚合、格式和质量失败拆分仍需开发，不能从修复原因随意推算完整历史结果。

## 5. 幻觉怎样识别

先分清问题，不能把所有错误都叫幻觉。

| 类型 | 例子（虚构） | 如何识别 |
| --- | --- | --- |
| 无依据事实/经历 | 没证据却写“用了三个月从不跑音” | 分句提取主张，关联可见证据；不能证实时记 unknown/unsupported，不自动判客观假 |
| 引用伪造/串台 | 引用别的任务、未渲染行 | 现有任务范围/实际渲染 registry 硬检查 |
| 评分与文本冲突 | 1 星却只称赞且无解释 | 情感规则只做候选筛查；人工判定，不把关键词匹配当真值 |
| 偏好过度泛化 | 一条短评就断言用户永久喜欢某品牌 | 检查历史数量、时间范围与主张强度，禁止把稀疏历史包装成确定偏好 |
| 指令注入/参考照抄 | 把参考中的指令当系统规则 | 已知注入启发式与 8-gram 重合告警；不是完整攻击防御 |
| 纯预测误差 | 模拟 4 星，实际 2 星 | 用评分指标诊断；主观评分偏差本身不等于事实幻觉 |

已有引用检查能证明“引用在展示范围内”，不能证明“这句话被该引用支持”。**语义主张与证据支持检查尚未完整实现。**商品规格/元数据也必须有可信来源与截至时点，不能把抓取后的商品页当历史事实。

### 发现问题后按这个顺序调整

1. 记录安全错误类别、证据指纹和状态；原文只留获准本地，避免日志泄露。
2. 检查数据泄漏、工具视图、实际渲染和评分 join，先排除评测错误。
3. 缩小允许主张：只有证据支持的事实；禁止无依据价格、耐用时长、购买经历。所有输出保持 `simulated=true`。
4. 优化参考选择和画像，减少噪声与重复统计；不是简单加长 prompt。
5. 条件修复只指出具体违规和可用证据，剩余预算允许才最多一次；失败不入 Memory。
6. 主张仍不能支持时删除主张或降级/拒绝；不得用更自信的措辞替代证据。
7. 调低 temperature 可以做验证集对照，但不能保证消除幻觉；是否改善需固定样本复测。
8. 用分句支持率/无依据主张率和人工评审核验变化，不能只看 RMSE；必要时为产品事实单独增加可信证据工具，而不是再建一个生成 Agent。

## 6. 是否能存储用户行为记忆

**现在：有真实历史读取和运行内生成 Memory；没有跨运行的真实行为记忆库。**

- `local_memory.py` 保存 Agent 生成的文本/评分，默认每用户最多 8 条，进程内、每实验 fresh store。
- `ReliableMemoryStore` 增加最终 success 写入、重复写拒绝、用户/run 隔离、UTC 日严格更早召回和渲染前再次核验。
- 两者不持久化到磁盘；重启后不保留。历史数据文件虽在磁盘，不等于 Agent 已有在线行为事件存储能力。
- generated 文本/评分不是用户真实反馈，也不改变模型权重；只能作表达参考，不进入可信评分统计。

### 持久行为记忆的后续实现（尚未实施）

建议先使用本地 SQLite，不先上向量库。划分三个来源：

```text
ObservedEvent       明确来源的真实历史/用户确认反馈
DerivedPreference   可重算摘要，保留所用事件与截至时间
GeneratedMemory     Agent 的模拟输出，独立 run/config 与过期策略
```

拟字段：匿名用户键、dataset/version、event_id、item、UTC event_time、observed_at、kind、payload、origin、source_hash；生成记忆另有 task/execution/run/config、quality_status。真实行为与生成内容不能共用无来源的“记忆文本池”。

逐步做：

1. 定义 `ObservedEvent` 与 `GeneratedMemory` 类型及来源枚举，先用合成事件测试。
2. 建 SQLite schema/迁移与幂等 event_id；只存获准字段，文件位于 E 盘 ignored 数据目录。
3. 只从已核验真实历史或用户明确确认反馈写 observed；模型猜测永不写 observed。
4. 读取时限制 dataset、用户、截至时间、条数和字节；扣留所有评测目标及副本。持久化不能绕过冻结历史协议。
5. 真实摘要仅从 eligible observed 事件重算；记录来源数、时间范围和置信限制。更正/删除事件后同步重算。
6. 生成记忆只在成功后写一次；按 run/config/用户和 UTC 日过滤；新消融运行不能继承旧生成 store。
7. 补保留期限、删除与可审计计数；不把化名等同完整匿名化。
8. 验收重启可读真实事件、重复不增、跨用户/未来/扣留目标不可读、错误模拟输出不写、删除后摘要不残留。

不把生成结果保存下来再当正确标签“自我学习”。如果只需要当前 400 任务消融，现有运行内 store 足够，先完成评测再增加数据库。

## 7. 人工评审方案（只设计，未执行）

拟定 20 个有可见历史的任务×两种条件=40 条评论；两名用户指定的真实评审者，各评价两个维度，合计 80 份评审/160 个维度评分。

- 风格匹配：1=语言/语气/详略明显偏离历史；3=部分匹配；5=整体高度匹配。
- 评分—评论一致性：1=评分与表达明显冲突；3=存在歧义；5=倾向及细节与评分一致。
- 盲化模型/Memory 标签，随机呈现；评审可见安全历史、模拟评分与文本，不显示模型配置。
- 从预先固定的候选任务抽样，不先挑最好看的输出；无法产生文本的任务计入覆盖，不伪造评审样本。
- 用于调整 prompt 的人评应取开发/验证任务；测试集人评仅作末端验证。若根据测试人评调整模型，后续需新 holdout，不能反复用同一测试集宣称独立验证。
- 有效评论不足 40 则报告实际数量；无历史的风格项标 NA。说明选择成功输出人评带来的条件样本偏差。
- 保存匿名评审者标识、版本、评分及评分来源；报告分维度分布、分歧和一致性，人工评分不能由 fake 或 LLM judge 冒充。

样本、展示的数据范围、评审者和可能费用必须先确认；本轮没有实际组织人评。
